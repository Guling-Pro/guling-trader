# 消费方契约需求清单（版本冻结前终审）

需求方：guling-loop（自动化操盘 daemon，多进程并发消费：回撤闸 120s/成交巡检 300s/
哨兵常驻/分钟微操/新闻环持仓拉取）。背景：本版本发布后长期冻结，以下按实测账逐条提出——
每条带消费侧实证与依赖点，**P0=不钉死则消费侧永远靠实测记忆与兼容代码硬扛**。

## P0 · 回执契约（结构性，冻结后无法再改）

**C1 统一响应信封（无例外形）**。所有工具（含 buy/sell/cancel）一律：
`{"status": "succeed"|"failed"|"busy", "code": <机器枚举串>, "data": <载荷或 null>,`
`"error": {"class": <枚举>, "broker_msg": <柜台原文>} | null, "contract_version": "2"}`。
消灭现状两形（查询带 data 包裹、买卖回执裸体——消费侧实证）：**不留兼容形，一步到位**，
消费侧同步改（我方一次性成本，换长期零兼容代码）。

**C2 错误机器分类（v2：两层分类＋unknown 兜底）**。拒单/失败禁走 isError 富文本单通道。
分两层：**结构性判定**（前置校验/busy/超时/策略未设置/基线失败/表头拒收）→ 确定 class；
**柜台原文** → 关键词表尽力映射（资金不足/价格超限/停牌…）＋**强制 unknown 兜底**＋
broker_msg 原文。契约条款：**消费侧必须把 unknown 当「不可自动重试」处理**——误分类比
不分类危险（「必放弃」错判「可重试」=真实重复下单），枚举可随版本增补、unknown 兜底
使冻结与列全不冲突。

**C3 orders_active 只返回在飞单（v2：未识别态保守方向）**。已撤/已成/废单不出现在该表；
每行结构钉死：`{client_order_id(可null), entrust_no, 证券代码, 证券名称, 方向, 委托价,`
`委托数量, 已成数量, 状态}`，状态值域枚举＋unknown 兜底；**状态无法识别时按「在飞」返回
禁过滤掉**——宁可多给一行，不可把活着的挂单藏起来（那正是错表最险的失效模式）。
全历史单据另开 `orders_all`（P1）。

**C4 client_order_id 规格（v2 修正：前提复核后改写）**。40 字符截断经复核=**消费侧自定**
（生成键后自截），非柜台限制——原文相关句作废。终态契约：①消费侧承诺 coid ≤40 字符、
**全局唯一含账户维度**（键规格将加账户段——受控端对账户盲切无感知，唯一性由生成方保证，
幂等键单键即可）；②coid 不触柜台，orders_active/orders_filled 的回显=受控端本地台账
（coid↔entrust_no）join，**尽力而为**：回查失败的超时单与人工/外部单回显 null——契约明示
此链结构性会断；③消费侧对账以 entrust_no/合同编号 为主键、coid 为增强关联（null≠越权单，
消费侧对账逻辑自适配）。

**C5a 提交幂等（v2 措辞：unknown 收窄非消灭）**。buy/sell/cancel 以 client_order_id 为
幂等键：**同 id 重复提交绝不产生第二次点击，返回首次提交记录的状态；该状态可能为
unknown，直到回查确认为止**。价值不变：超时后消费侧的安全动作从「不敢重试留孤儿单」
变「原 id 重发」。台账落盘、保留 ≥5 交易日；**台账损坏时拒绝下单，禁静默降级为无幂等**。

**C5b 按 client_order_id 查单**。`query_order(coid)` → 未受理/已挂/部成/已成/已撤/
**未知(需人工)**＋回执快照与判据；entrust_no 未知时按 (代码,方向,数量,价格,时间窗) 启发式
匹配，歧义（如两笔同参重复单）即返回 未知(需人工)——未知是合法返回态非失败。

**C6 字段类型与单位契约（v2 补两条）**。数值字段一律 JSON number（金额=元、取整到**分**；
数量=股）；**THS 空占位符（--/空串）一律映射 null 禁映射 0**（0 会被当真实数字——消费侧
None≠0 纪律的接口层对应物）；键名钉死并与真实返回体逐字段对齐；`仓位占比(%)` 类带符号
键名更名。键名保留中文是有意选择非妥协（与同花顺界面列名同字面，对屏审计零翻译成本）。

**C1 附则**：contract_version 同时暴露在 initialize 回执——消费侧握手即知对面版本，
不必先调业务工具试探。**B2 附则**：成交表时间列无日期，受控端补的日期来自本机时钟非
柜台时间——写进 PROTOCOL.md，消费侧按此对账。

**C7 契约即测试**。tools_schema.json 升为规范件：每次发版 CI 用真实（或录制）返回体
逐字段断言 schema——冻结的前提是漂移可检测，否则「很久不改」等于「坏了很久没人知道」。
消费侧承诺同构的契约测试电池作对侧回归哨。

## P0 · 网关契约（mcp.guling.pro，根因已坐实项）

**G1 挂起配对键=session+id**。已坐实：handlePairedRPC 拿客户端裸 JSON-RPC id 当配对键，
消费侧多进程同 id 即串线（2026-08-03 balance 错表 12 次的根因链条）。要求：按
(session, id) 配对；**id 唯一性不得作为客户端契约义务**——客户端守 JSON-RPC 域内唯一即合法。

**G2 id 类型透传**。消费侧现用字符串 id（`gl-<pid>-<seq>`），要求全链路（网关↔受控端）
string/number 双型原样回传，禁转型（转 int 即配对断）。

**G3 busy/超时语义钉死**。win_lock 5s busy 回执与 dispatcher 25s 超时的返回形态、消费侧
应退避的建议间隔，写进 PROTOCOL.md——busy 是背压信号，消费侧愿意退避，但要认得出来。

**G4 会话生命周期**。sid 过期/失效的返回形态钉死（消费侧现「任何异常即弃 sid 重握手」，
粗但能用；钉死后可精确区分「会话过期」与「真故障」）。

## P1 · 行为项

**B1 settlement 表头入 table_guard**（消费侧即将消费该工具，勿留校验空白）。
**B2 成交时间格式与时区钉死**（现无契约；回验/对账按字符串前缀匹配在硬扛）。
**B3 空仓/空表语义永久锁定**：空表=code 0+data []（本次修复已带回归测试，此条仅要求
写进 PROTOCOL.md 成为契约而非实现细节——「真没有」与「拿不到」的区分是消费侧一切
降级判断的地基）。

## 验收

消费侧可代跑的契约测试：C1-C7 逐条以真实调用断言（我方 selftest 已有错表/回执配对七格，
契约钉死后扩成契约测试电池，长期作双方回归哨）。本清单为**最优形态定稿**：不含
「保持现状亦可」类兼容退路——消费侧同步改造成本（信封两形兼容删除、数值类型切换）
已评估为一次性可承受，由需求方自担。
